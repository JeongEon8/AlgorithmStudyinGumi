# [PGS - Lv2] 03_124 나라의 숫자

## ⏰**time**

32분

## :pushpin: **Algorithm**

* 진법 변환
* 수학
* StringBuilder

## ⏲️**Time Complexity**

$O(\log N)$

반복문이 한 번 돌 때마다 `n`을 대략 3으로 나눈다.

```java
n /= 3;
```

또는 나머지가 `0`인 경우에도

```java
n = n / 3 - 1;
```

로 값이 빠르게 감소한다.

따라서 반복 횟수는 124 나라 숫자의 자릿수에 비례하고, 자릿수는 약 $\log_3 N$이므로 전체 시간 복잡도는 $O(\log N)$이다.

## :round_pushpin: **Logic**

1. 124 나라의 숫자는 일반적인 3진법과 비슷하지만 사용할 수 있는 숫자가 `1`, `2`, `4`뿐이다.

   즉, 일반적인 3진법에서 사용하는 `0`이 존재하지 않는다.

2. 현재 숫자를 3으로 나눈 나머지를 구한다.

   ```java
   int remainder = n % 3;
   ```

   나머지가 `1` 또는 `2`라면 그대로 124 나라의 한 자리 숫자로 사용할 수 있다.

3. 나머지가 `1` 또는 `2`인 경우에는 일반적인 진법 변환처럼 `n`을 3으로 나눈다.

   ```java
   n /= 3;
   ```

4. 나머지가 `0`인 경우에는 124 나라에 `0`이 없으므로 `4`로 변환한다.

   ```java
   if (remainder == 0) {
       remainder = 4;
   }
   ```

5. 나머지가 `0`이었던 경우에는 단순히 `n / 3`으로 넘어가면 자릿수가 하나 더 생기므로 몫에서 1을 빼준다.

   ```java
   n = n / 3 - 1;
   ```

   예를 들어 `n = 3`인 경우:

   ```text
   3 % 3 = 0

   remainder = 4
   n = 3 / 3 - 1 = 0
   ```

   따라서 `3`은 124 나라에서 `4`가 된다.

6. 진법 변환 과정에서 구한 나머지는 낮은 자리부터 나오므로 `StringBuilder`에 순서대로 저장한다.

   ```java
   sb.append(remainder);
   ```

7. 모든 자릿수를 구한 뒤 저장된 순서를 뒤집어 최종 결과를 만든다.

   ```java
   return sb.reverse().toString();
   ```

## :black_nib: **Review**

* 처음에는 일반적인 3진법 변환처럼 나머지를 이용하면 될 것이라고 생각했지만, 124 나라에는 `0`이 없다는 점 때문에 추가적인 처리가 필요했다.
* `n % 3 == 0`일 때 나머지를 `4`로 바꾸고 몫에서 1을 빼주는 것이 핵심이었다.
* 나머지를 구하면 낮은 자리부터 만들어지기 때문에 `StringBuilder`에 저장한 뒤 마지막에 `reverse()`를 사용했다.
* 문자열 앞에 계속 문자를 추가하는 방식보다 `StringBuilder`에 뒤로 추가한 뒤 한 번 뒤집는 방식이 더 효율적이었다.
* `n`이 매 반복마다 약 3분의 1로 줄어들기 때문에 시간 복잡도는 $O(\log N)$이다.
