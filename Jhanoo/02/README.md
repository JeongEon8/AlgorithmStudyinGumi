# [PGS - Lv2] 02_호텔 대실

## ⏰**time**

18분

## :pushpin: **Algorithm**

* 누적합
* 차분 배열
* 시뮬레이션
* 문자열 파싱

## ⏲️**Time Complexity**

$O(N)$

`N`은 예약의 개수이다.

각 예약마다 시작 시각과 종료 시각을 분 단위로 변환하고, 시간 변화량을 배열에 기록하는 데 $O(N)$이 걸린다.

이후 시간 배열을 한 번 순회하는데, 배열 크기는 하루 1,440분과 청소 시간 10분을 고려한 고정 크기이므로 상수 시간으로 볼 수 있다.

따라서 전체 시간 복잡도는 $O(N)$이다.

## :round_pushpin: **Logic**

1. 예약 시각을 비교하기 쉽도록 모든 시간을 분 단위로 변환한다.

   예를 들어 `15:30`은 다음과 같이 계산한다.

   ```text
   15 × 60 + 30 = 930
   ```

   ```java
   private int convert(String time) {
       String[] hhmm = time.split(":");
       int hour = Integer.parseInt(hhmm[0]);
       int minute = Integer.parseInt(hhmm[1]);

       return hour * 60 + minute;
   }
   ```

2. 퇴실 후 청소 시간 10분 동안은 해당 객실을 사용할 수 없다.

   따라서 종료 시각에 10분을 더해 실제 객실 사용 종료 시각으로 계산한다.

   ```java
   int start = convert(book[0]);
   int end = convert(book[1]) + 10;
   ```

3. 각 분마다 모든 예약을 직접 확인하는 대신 차분 배열을 사용한다.

   예약 시작 시각에는 사용 중인 객실 수가 1개 증가하고, 청소가 끝나는 시각에는 1개 감소한다.

   ```java
   timeline[start]++;
   timeline[end]--;
   ```

4. 객실 사용 구간은 `[start, end)` 형태로 처리한다.

   즉, `end` 시각부터는 청소가 끝나 새로운 손님이 같은 객실을 사용할 수 있다.

   예를 들어 예약 종료가 `15:20`이라면 청소가 끝나는 `15:30`에서 객실 사용 수를 감소시킨다.

5. 배열을 앞에서부터 순회하면서 누적합을 계산한다.

   현재 시각에 사용 중인 객실 수는 이전 시각까지의 변화량을 모두 더한 값이다.

   ```java
   int rooms = 0;

   for (int change : timeline) {
       rooms += change;
   }
   ```

6. 누적합을 계산하면서 동시에 가장 많이 사용된 객실 수를 저장한다.

   ```java
   answer = Math.max(answer, rooms);
   ```

7. 모든 시각을 확인한 뒤 가장 많이 겹친 예약 수를 반환한다.

   이 값이 필요한 최소 객실 수이다.

   ```java
   return answer;
   ```

## :black_nib: **Review**

* 처음에는 각 분마다 모든 예약 구간을 확인하는 방식으로 접근했지만, 차분 배열을 사용하면 시작과 종료 시각만 기록해 더 간단하게 처리할 수 있었다.
* 종료 시각에 바로 객실을 비우는 것이 아니라 청소 시간 10분을 더한 시각까지 사용 중으로 계산해야 했다.
* 사용 구간을 `[시작 시각, 청소 종료 시각)`으로 생각하면 같은 시각에 청소가 끝나고 다음 예약이 시작되는 경우도 자연스럽게 처리할 수 있었다.
* 시간 범위가 하루 단위로 작고 고정되어 있어 우선순위 큐보다 시간 배열을 사용하는 풀이가 구현상 간단했다.
* 배열의 누적합 중 최댓값이 동시에 필요한 객실 수라는 점이 핵심이었다.
