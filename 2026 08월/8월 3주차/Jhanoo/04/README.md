# [PGS - Lv2] 04_하노이의 탑

## ⏰**time**

20분

## :pushpin: **Algorithm**

- 재귀
- 분할 정복
- 하노이의 탑

## ⏲️**Time Complexity**

$O(2^N)$

원판 `N`개를 옮기기 위해서는 다음과 같이 재귀적으로 작업한다.

```
N개 이동
= N-1개 이동
+ 가장 큰 원판 1개 이동
+ N-1개 이동
```

따라서 점화식은 다음과 같다.

```
T(N) = 2T(N-1) + 1
```

이를 풀면 총 이동 횟수는

```
2^N - 1
```

이 된다.

각 이동을 `answer` 배열에 한 번씩 기록하므로 전체 시간 복잡도는 $O(2^N)$이다.

## :round_pushpin: **Logic**

1. 하노이의 탑에서 `N`개의 원판을 `from` 기둥에서 `to` 기둥으로 옮기려면 먼저 위에 있는 `N-1`개의 원판을 보조 기둥 `via`로 옮겨야 한다.

   ```
   from → via
   ```

2. 그다음 가장 큰 원판 하나를 목적지 기둥으로 옮긴다.

   ```
   from → to
   ```

3. 마지막으로 보조 기둥에 옮겨두었던 `N-1`개의 원판을 목적지 기둥으로 옮긴다.

   ```
   via → to
   ```

4. 이 과정을 재귀 함수로 표현한다.

   ```
   hanoi(n - 1, from, via, to);
   
   answer[idx++] = new int[]{from, to};
   
   hanoi(n - 1, via, to, from);
   ```

5. 원판이 하나만 남으면 더 이상 나눌 필요 없이 바로 목적지로 이동시키면 된다.

   ```
   if (n == 1) {
       answer[idx++] = new int[]{from, to};
       return;
   }
   ```

6. 하노이의 탑에서 필요한 총 이동 횟수는 `2^N - 1`이므로 정답 배열의 크기를 미리 생성한다.

   ```
   answer = new int[(1 << n) - 1][2];
   ```

   `1 << n`은 비트 시프트 연산으로 `2^n`을 의미한다.

7. 최초에는 1번 기둥의 모든 원판을 3번 기둥으로 옮겨야 하므로 다음과 같이 호출한다.

   ```
   hanoi(n, 1, 3, 2);
   ```

   각 매개변수의 의미는 다음과 같다.

   ```
   from : 출발 기둥
   to   : 목적지 기둥
   via  : 보조 기둥
   ```

8. 재귀 호출 과정에서 실제 원판 이동이 발생할 때마다 `answer` 배열에 이동 정보를 순서대로 저장한다.

   ```
   answer[idx++] = new int[]{from, to};
   ```

9. 모든 재귀 호출이 종료되면 기록된 이동 순서를 반환한다.

   ```
   return answer;
   ```

## :black_nib: **Review**

- 하노이의 탑은 이동 방법을 탐색하는 문제가 아니라 `N-1개 이동 → 가장 큰 원판 이동 → N-1개 이동`이라는 순서가 정해져 있는 재귀 문제였다.
- `N`개의 원판을 옮기는 문제를 `N-1`개의 원판을 옮기는 동일한 문제로 나눌 수 있다는 점이 핵심이었다.
- 이동 횟수가 `2^N - 1`로 미리 정해져 있으므로 `List`에 저장한 뒤 배열로 변환하지 않고 처음부터 `int[][]` 크기를 생성할 수 있었다.
- `(1 << n) - 1`을 이용하면 `2^N - 1`을 간단하게 계산할 수 있었다.
- 재귀 문제에서는 현재 문제를 더 작은 동일한 형태의 문제로 어떻게 정의할 수 있는지 찾는 것이 중요하다는 점을 확인했다.
