# [PGS - Lv2] 01_우박수열 정적분

## ⏰**time**

51분

## :pushpin: **Algorithm**

- 누적합
- 수학
- 시뮬레이션
- 우박수열

## ⏲️**Time Complexity**

$O(N + R)$

`N`은 `k`가 1이 될 때까지 만들어지는 우박수열의 구간 개수이고, `R`은 `ranges`의 개수이다.

우박수열을 생성하면서 각 구간의 넓이를 한 번씩 계산하므로 $O(N)$이 걸린다.

각 구간의 넓이는 누적합으로 저장되어 있기 때문에 하나의 정적분 범위는 두 누적합의 차이만으로 $O(1)$에 계산할 수 있다.

따라서 모든 `ranges`를 처리하는 데 $O(R)$이 걸리고, 전체 시간 복잡도는

```text
O(N + R)
```

이다.

## :round_pushpin: **Logic**

1. 우박수열을 만들면서 각 `x` 좌표까지의 넓이를 누적해서 저장한다.

   최초 위치의 누적 넓이는 `0`이다.

   ```java
   List<Double> arr = new ArrayList<>();
   arr.add(0.0);
   ```

2. 현재 값 `k`가 1이 될 때까지 우박수열 규칙을 적용한다.

   ```java
   if (k % 2 == 0)
       k /= 2;
   else
       k = k * 3 + 1;
   ```

3. 우박수열에서 두 점 사이의 `x` 좌표 차이는 항상 `1`이다.

   따라서 이전 값이 `prev`, 다음 값이 `k`라면 두 점 사이의 넓이는 사다리꼴의 넓이 공식을 이용해 구할 수 있다.

   ```text
   넓이 = (prev + k) × 1 / 2
        = (prev + k) / 2
   ```

   이를 이전까지의 누적 넓이에 더해 저장한다.

   ```java
   arr.add(arr.get(i++) + (double) (prev + k) / 2);
   ```

4. 우박수열이 1에 도달했을 때 만들어진 전체 구간의 개수를 `n`으로 저장한다.

   ```java
   int n = arr.size() - 1;
   ```

   `arr`에는 시작점의 누적 넓이 `0.0`도 포함되어 있으므로 실제 구간 개수는 `size - 1`이다.

5. 각 `range = [a, b]`에서 실제 적분 범위는 문제 조건에 따라 다음과 같다.

   ```text
   시작점 = a
   끝점   = n + b
   ```

6. 시작점이 끝점보다 크다면 유효하지 않은 구간이므로 `-1.0`을 저장한다.

   ```java
   if (a > n + b) {
       answer[i++] = -1.0;
       continue;
   }
   ```

7. 유효한 구간이라면 누적합을 이용해 넓이를 구한다.

   ```java
   answer[i++] = arr.get(n + b) - arr.get(a);
   ```

   예를 들어 `arr[x]`가 `0`부터 `x`까지의 누적 넓이라면,

   ```text
   a부터 b까지의 넓이
   = 0부터 b까지의 넓이 - 0부터 a까지의 넓이
   ```

   와 같이 계산할 수 있다.

8. 모든 `range`에 대한 정적분 결과를 반환한다.

   ```java
   return answer;
   ```

## :black_nib: **Review**

- 처음에는 각 `range`마다 직접 정적분 구간을 순회하는 방법을 생각할 수 있지만, 같은 우박수열에 대해 여러 범위의 넓이를 반복해서 계산해야 하므로 누적합을 활용했다.
- 우박수열의 인접한 두 점 사이에서는 직선으로 연결되므로 각 구간의 넓이는 사다리꼴 넓이 공식으로 계산할 수 있었다.
- `x` 좌표의 간격이 항상 1이기 때문에 `(이전 높이 + 현재 높이) / 2`만으로 구간 넓이를 구할 수 있었다.
- 구간별 넓이를 누적해서 저장하면 각 정적분 결과를 두 누적합의 차이만으로 `O(1)`에 계산할 수 있었다.
- `ranges`의 두 번째 값 `b`는 마지막 지점을 기준으로 하는 상대 좌표이므로 실제 끝점이 `n + b`라는 점을 주의해야 했다.
- 시작점 `a`가 끝점 `n + b`보다 크면 문제 조건에 따라 `-1.0`을 반환해야 했다.
