# [PGS - Lv2] 02_디펜스 게임

## ⏰**time**

25분

## :pushpin: **Algorithm**

* Greedy
* Priority Queue
* Max Heap

## ⏲️**Time Complexity**

$O(N \log N)$

`N`은 `enemy` 배열의 길이이다.

각 웨이브마다 적의 수를 우선순위 큐에 한 번 삽입한다.

```java
pq.offer(enemy[i]);
```

최대 힙의 삽입 연산은 $O(\log N)$이다.

병사가 부족해졌을 때 지금까지 등장한 가장 큰 웨이브를 꺼내 무적권을 적용한다.

```java
pq.poll();
```

삭제 연산 역시 $O(\log N)$이다.

각 웨이브는 우선순위 큐에 최대 한 번 들어가고 최대 한 번 제거되므로 전체 시간 복잡도는 $O(N \log N)$이다.

## :round_pushpin: **Logic**

1. 각 웨이브에서 무적권을 사용할지 바로 결정하지 않고, 우선 모든 웨이브를 병사로 막았다고 가정한다.

   ```java
   soldier -= enemy[i];
   ```

2. 지금까지 등장한 웨이브의 적 수를 최대 힙에 저장한다.

   ```java
   PriorityQueue<Integer> pq =
       new PriorityQueue<>(Collections.reverseOrder());

   pq.offer(enemy[i]);
   ```

   최대 힙을 사용하면 지금까지 등장한 웨이브 중 가장 적의 수가 많은 웨이브를 바로 찾을 수 있다.

3. 현재 웨이브를 막은 뒤 병사가 부족해졌다면, 지금까지 등장한 웨이브 중 가장 큰 웨이브에 무적권을 사용했다고 처리한다.

   ```java
   while (soldier < 0 && k > 0) {
       soldier += pq.poll();
       k--;
   }
   ```

   예를 들어 지금까지 다음 웨이브를 병사로 처리했다고 가정한다.

   ```text
   4, 2, 7
   ```

   병사가 부족해졌다면 가장 큰 `7`을 최대 힙에서 꺼내 병사를 다시 복구한다.

   ```text
   4 → 병사 사용
   2 → 병사 사용
   7 → 무적권 사용
   ```

   즉, 이전 선택을 가장 유리한 형태로 수정하는 것이다.

4. 무적권을 사용할 수 있다면 적의 수가 가장 많은 웨이브에 사용하는 것이 항상 유리하다.

   큰 웨이브를 무적권으로 처리할수록 더 많은 병사를 절약할 수 있기 때문이다.

5. 무적권을 모두 사용한 이후에도 병사가 음수라면 현재 웨이브를 막을 수 없는 것이므로 반복을 종료한다.

   ```java
   if (soldier < 0 && k == 0) {
       break;
   }
   ```

6. 반복문 변수 `i`는 현재까지 성공적으로 막은 웨이브의 수와 동일하다.

   따라서 반복이 종료된 시점의 `i`를 반환한다.

   ```java
   return i;
   ```

## :black_nib: **Review**

* 처음에는 각 웨이브에서 무적권을 사용하는 경우와 사용하지 않는 경우를 BFS로 모두 탐색하는 방법을 생각했다.
* 하지만 웨이브마다 선택지가 두 개씩 생기기 때문에 경우의 수가 매우 커질 수 있어 BFS는 적합하지 않았다.
* 무적권은 지금까지 등장한 웨이브 중 적의 수가 가장 많은 웨이브에 사용하는 것이 가장 많은 병사를 아낄 수 있다는 점을 이용해 그리디하게 해결할 수 있었다.
* 현재 웨이브에서 무적권 사용 여부를 바로 확정하지 않고, 일단 병사로 처리한 뒤 병사가 부족해지면 과거의 가장 큰 웨이브를 무적권 처리로 바꾸는 방식이 핵심이었다.
* 최대 힙을 사용하면 지금까지 등장한 가장 큰 웨이브를 $O(\log N)$에 찾을 수 있었다.
* `while`문을 사용했지만 한 웨이브를 처리하면서 실제로 여러 번 복구되는 경우는 제한적이며, 각 원소는 힙에서 최대 한 번 제거되므로 전체 시간 복잡도는 $O(N \log N)$이다.
